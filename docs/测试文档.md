# RAG 系统简介

检索增强生成（Retrieval-Augmented Generation，RAG）是一种结合信息检索与大语言模型的架构。它先通过向量检索从知识库中召回与用户问题相关的文本片段，再把召回结果注入提示词交给大模型生成答案，从而有效缓解模型幻觉、让回答有据可查。

## 向量化与向量数据库

文档导入知识库时，首先由嵌入模型（如 BGE-M3）将文本块编码为高维向量。BGE-M3 是一种多功能嵌入模型，支持稠密检索、稀疏检索和多向量检索，输出的稠密向量维度为 1024 维，对中英文均有良好效果。

向量数据库负责存储向量并提供近似最近邻搜索。Milvus 是目前最流行的开源向量数据库之一，支持十亿级向量规模，采用存算分离架构：etcd 负责元数据存储，MinIO 负责对象存储，QueryNode 和 DataNode 分别承担查询与数据写入。

## 文本切分策略

原始文档通常很长，无法整篇向量化，需要先切分为合适大小的文本块。常用切分方式包括固定长度切分、按标点切分、按标题层级切分等。块太小会丢失上下文，块太大则检索精度下降，一般以 512 到 800 token 为宜。

切分时可以保留重叠部分，让相邻块之间共享一部分内容，避免关键信息被切断在块边界上。同时应当把文件名、章节标题等元数据附加到每个块上，方便检索时过滤和溯源。

## 混合检索与重排序

纯向量检索对精确匹配的关键词不敏感，因此工程上常采用混合检索：同时执行向量检索与 BM25 关键词检索，再通过 RRF（倒数排名融合）合并两路结果。重排序模型（Reranker）会在召回之后对候选片段进一步精排，显著提升最终答案的质量。

## 检索质量评估

评估 RAG 系统通常关注两个指标：召回率衡量相关片段是否被找回，精确率衡量找回的片段是否真的相关。实际项目中还会通过构建标准问答对数据集，对比答案的忠实度与相关性，持续迭代切分参数与检索策略。
